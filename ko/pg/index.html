01결제 흐름 이해하기

KORATECH 결제는 요청 → 인증 → 승인 3단계로 이루어집니다. 구매자 인증이 끝나면 successUrl로 이동하고, 가맹점 서버가 승인 API를 호출해야 결제가 최종 완료됩니다.

  1. 결제 요청클라이언트에서 SDK로 결제창을 엽니다.
  2. 구매자 인증카드사·간편결제 인증을 진행합니다.
  3. 리다이렉트paymentKey, orderId, amount가 전달됩니다.
  4. 서버 승인승인 API를 호출하면 DONE 상태가 됩니다.
💡인증 후 10분 이내에 승인 API를 호출하지 않으면 결제가 자동으로 만료(EXPIRED)됩니다.

02API 키 발급

가맹점 계약 전에도 테스트 키로 모든 기능을 사용할 수 있습니다. 클라이언트 키는 브라우저에서, 시크릿 키는 서버에서만 사용합니다.

시크릿 키test_sk_KT2026zXLkKEypNArWmo50nmlJ4b
⚠️시크릿 키가 클라이언트 코드나 GitHub에 노출되지 않도록 주의하세요. 노출 시 즉시 콘솔에서 재발급하세요. (위 키는 데모용 예시 값입니다.)

04결제 승인 (API)

successUrl로 전달된 값을 서버에서 검증한 뒤 승인 API를 호출합니다. 인증은 Basic base64(시크릿키:) 방식입니다.

POSThttps://api.koratechit.com/v1/payments/confirm
파라미터타입필수설명
paymentKeystring필수결제의 고유 키. 최대 200자
orderIdstring필수가맹점 주문번호. 영문·숫자·- _, 6–64자
amountinteger필수결제 금액. 요청 시 금액과 반드시 일치해야 함
GET/v1/payments/{paymentKey}— 결제 조회
POST/v1/payments/{paymentKey}/cancel— 결제 취소 (부분취소 지원)

05웹훅 설정

가상계좌 입금, 결제 취소 등 비동기 이벤트는 웹훅으로 전달됩니다. 요청 헤더 KT-Signature로 서명을 검증하세요.

import crypto from 'crypto';

app.post('/webhooks/koratech', express.raw({ type: 'application/json' }), (req, res) => {
  const sig = req.header('KT-Signature');
  const expected = crypto.createHmac('sha256', process.env.KT_WEBHOOK_SECRET)
    .update(req.body).digest('hex');
  if (sig !== expected) return res.sendStatus(401);

  const event = JSON.parse(req.body);
  if (event.eventType === 'PAYMENT_STATUS_CHANGED') {
    // event.data.status: DONE | CANCELED | WAITING_FOR_DEPOSIT ...
  }
  res.sendStatus(200); // 10초 이내 200 응답, 실패 시 최대 7회 재전송
});

06결제 상태 코드

결제 객체의 status 필드 값입니다.

상태설명
READY결제가 생성되고 구매자 인증 전인 상태
IN_PROGRESS구매자 인증 완료, 승인 API 호출 대기
WAITING_FOR_DEPOSIT가상계좌 발급 완료, 입금 대기
DONE결제 승인 완료
CANCELED전액 취소
PARTIAL_CANCELED부분 취소
ABORTED승인 실패
EXPIRED유효시간 경과로 만료

07에러 코드

에러 응답은 { "code": "...", "message": "..." } 형식으로 반환됩니다.

HTTP코드설명 · 조치
400INVALID_REQUEST필수 파라미터 누락 또는 형식 오류
400AMOUNT_MISMATCH요청 금액과 승인 금액 불일치 — 주문 금액을 확인하세요

404NOT_FOUND_PAYMENT존재하지 않는 paymentKey
409ALREADY_PROCESSED이미 승인 또는 취소된 결제
500PROVIDER_ERROR일시적 오류 — 잠시 후 재시도 (멱등키 사용 권장)
